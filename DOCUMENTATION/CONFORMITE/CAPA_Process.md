# CAPA Process - Corrective and Preventive Actions

## 1. Purpose and Scope

### Purpose
This procedure defines the process for identifying, analyzing, implementing, and verifying corrective and preventive actions (CAPA) to address non-conformities and prevent recurrence of problems in biomedical maintenance operations.

### Scope
This procedure applies to:
- Non-conformities identified through audits
- Non-conformities identified during maintenance
- Customer complaints and feedback
- Equipment failures and malfunctions
- Process deviations and gaps
- Regulatory findings

### Standards Referenced
- ISO 9001:2015 - Corrective Action Requirements (§10.2)
- ISO 13485:2016 - Medical Device Quality Management
- ISO 14971:2019 - Risk Management

---

## 2. Definitions

| Term | Definition |
|------|-----------|
| **Non-Conformity (NC)** | Failure to meet a specified requirement |
| **Corrective Action (CA)** | Action taken to eliminate the cause of a non-conformity |
| **Preventive Action (PA)** | Action taken to prevent occurrence of a potential non-conformity |
| **Root Cause** | Underlying reason why a problem occurred |
| **Effectiveness Check** | Verification that corrective/preventive action achieved intended result |
| **CAPA** | Acronym for Corrective and Preventive Actions |

## 4. Non-Conformity Identification and Registration

### Who Can Identify Non-Conformities:
- Internal auditors
- Quality manager
- Maintenance personnel
- Equipment users
- Management
- Customers
- Regulatory authorities

### Non-Conformity Registration

**Immediately Upon Discovery:**
1. Document the non-conformity
2. Record date and time discovered
3. Identify responsible person
4. Describe what is non-conforming
5. Note severity level

**Non-Conformity Register Entry:**
- NC Number (sequential, e.g., NC-2026-001)
- Date discovered
- Description of non-conformity
- Process/area affected
- Severity (Minor/Major/Critical)
- Source (Audit/Customer/Operation/Other)
- Assigned to (responsible party)

### Non-Conformity Severity Assessment

**Minor Non-Conformity:**
- Isolated occurrence
- No impact on patient safety
- No regulatory impact
- Procedure not followed in one instance
- Correction timeline: 30 days
- Example: Single incomplete intervention form

**Major Non-Conformity:**
- Systemic or repeated occurrence
- Potential impact on quality or safety
- Potential regulatory issue
- Procedure not followed consistently
- Correction timeline: 15 days
- Example: Multiple maintenance tasks not completed as scheduled

**Critical Non-Conformity:**
- Serious non-compliance with requirements
- Direct impact on patient safety
- Regulatory violation
- Immediate corrective action required
- Correction timeline: 3-5 days
- Example: Safety system failure not detected or reported

## 5. Root Cause Analysis

### When Required:
- All Major and Critical non-conformities
- Repeated occurrences of same problem
- Safety-related issues
- Customer complaints
- Regulatory findings

### Root Cause Analysis Methods

**5 Why's Method:**
1. Why did the non-conformity occur? → [Answer 1]
2. Why did [Answer 1] happen? → [Answer 2]
3. Why did [Answer 2] happen? → [Answer 3]
4. Why did [Answer 3] happen? → [Answer 4]
5. Why did [Answer 4] happen? → [Answer 5 - ROOT CAUSE]

**Fishbone (Ishikawa) Diagram:**
- People: Training, communication, roles
- Process: Procedures, steps, controls
- Equipment: Tools, resources, materials
- Environment: Conditions, location, access
- Methods: Approach, techniques, systems

**Process Flow Analysis:**
- Map the process step-by-step
- Identify where failure occurred
- Determine which step allowed problem
- Analyze controls at that step
- Identify missing or ineffective control

### Root Cause Verification:
1. Can we confirm this is the true cause?
2. Would fixing this prevent recurrence?
3. Is there supporting evidence?
4. Are there contributing factors?

## 6. Corrective Action Development

### Action Plan Components

**For Each Non-Conformity:**

1. **Immediate Action (If Needed)**
   - Contain the problem
   - Prevent further non-conformities
   - Protect patient safety
   - Stabilize the situation
   - Timeline: Immediate to 24 hours

2. **Root Cause Analysis**
   - Identify underlying cause
   - Document findings
   - Verify analysis
   - Timeline: 5-10 business days

3. **Corrective Action**
   - Address the root cause
   - Prevent recurrence
   - Specific and measurable
   - Assigned to responsible person
   - Realistic timeline
   - Examples:
     - Update procedure
     - Provide training
     - Change process
     - Implement control
     - Replace equipment

4. **Verification/Effectiveness Check**
   - How will we verify action worked?
   - What evidence will prove effectiveness?
   - Timeline for verification
   - Responsible person

### CAPA Form Contents:
- NC Number and description
- Severity classification
- Date identified
- Assigned to (responsible person)
- Root cause analysis
- Immediate action (if any)
- Corrective action description
- Target completion date
- Success criteria
- Verification method
- Sign-off by responsible person

## 7. Preventive Action Development

### Identifying Prevention Opportunities

**From Risk Assessment:**
- Potential hazards identified
- Risk areas identified
- High-risk equipment flagged

**From Trend Analysis:**
- Increasing failure rates
- Emerging patterns
- Environmental changes

**From Knowledge:**
- Industry best practices
- Regulatory updates
- Technology improvements

### Preventive Action Planning

**For Each Opportunity:**

1. **Opportunity Statement**
   - What could potentially go wrong?
   - How likely is it?
   - What would be the impact?

2. **Prevention Strategy**
   - Prevent problem from occurring
   - Increase robustness
   - Add safeguards
   - Examples:
     - Enhanced training
     - Preventive maintenance increase
     - New monitoring
     - Design change
     - New procedure

3. **Implementation Plan**
   - Specific action required
   - Responsible person
   - Timeline
   - Resources needed

4. **Effectiveness Verification**
   - How will we know if it worked?
   - Metrics to monitor
   - Timeline for assessment

## 8. CAPA Tracking and Management

### CAPA Register Maintenance

**Information Tracked:**
- CAPA number
- Type (Corrective/Preventive)
- Description
- Assigned person
- Target completion date
- Actual completion date
- Status (Open/In Progress/Closed)
- Notes and comments

### Status Categories

**Open:**
- Not yet started
- In assignment phase

**In Progress:**
- Work has begun
- On track to meet deadline
- No impediments

**At Risk:**
- Approaching deadline with incomplete work
- Potential obstacles identified
- Escalation may be needed

**Closed:**
- All actions completed
- Verification completed
- Effectiveness confirmed
- Documented closure

### Escalation Process

**When CAPA is At Risk:**
1. Notify responsible person and supervisor
2. Identify impediments
3. Develop recovery plan
4. Request additional resources if needed
5. Adjust timeline if necessary
6. Document changes and approvals

---

## 9. Implementation and Verification

### Implementation Phase

**Before Implementation:**
1. Communicate action to affected staff
2. Provide training if needed
3. Prepare resources
4. Update procedures/documentation
5. Schedule implementation date

**During Implementation:**
1. Execute action as planned
2. Document activities
3. Address any issues immediately
4. Communicate progress
5. Maintain records

**Verification Activities:**
1. Observe implementation
2. Collect evidence
3. Interview staff
4. Review documentation
5. Test functionality

### Effectiveness Check

**Timing:**
- Minimum 30 days after implementation
- Extended if longer time needed to observe impact
- Before formal closure

**Verification Methods:**
- Audit observations
- Process monitoring
- KPI measurement
- Trend analysis
- Customer feedback
- Staff feedback

**Criteria for Success:**
- Non-conformity does not recur
- Root cause is eliminated
- Process meets requirement
- Performance metric is met
- Documentation is complete

**If Ineffective:**
1. Analyze why action didn't work
2. Identify barriers to effectiveness
3. Develop revised action
4. Reimplement
5. Re-verify

---

## 10. CAPA Closure

### Closure Requirements

**Before Closure:**
- [ ] All action items completed
- [ ] Verification performed
- [ ] Effectiveness confirmed
- [ ] Documentation complete
- [ ] No evidence of recurrence
- [ ] Appropriate approvals obtained

### Closure Process

1. **Prepare closure documentation:**
   - Summarize actions taken
   - Present verification results
   - Demonstrate effectiveness
   - Document lessons learned

2. **Obtain approvals:**
   - Quality manager approval
   - Responsible person sign-off
   - Management review (if required)

3. **Record closure:**
   - Update CAPA register
   - Record closure date
   - Archive supporting documents
   - Communicate closure

4. **Share lessons learned:**
   - Communicate to affected areas
   - Update procedures if applicable
   - Train staff on improvements
   - Document lessons

- Are new risks emerging?

- Emerging trends

**Review:**
